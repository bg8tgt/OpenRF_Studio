一、修复：安装版打开「反算 / Smith L 型匹配 / 匹配」对话框会卡死

【病因】对话框在窗口还没映射到屏幕时就调用 grab_set()。
  Windows 上这会抛 TclError；更糟的是有些情况下 grab 抓上了，
  但窗口因为定位算到屏幕外而没有真正显示——主窗口被一个看不见的
  模态框抓住，全程序点不动，表现就是"弹窗不出来 + 卡死"。

【修法】
  1. 抓取推迟到窗口真正可见之后（winfo_viewable() 检查通过才 grab），
     失败最多重试 8 次，绝不无限重试
  2. 对话框定位钳制到屏幕可见范围内，绝不会落到屏幕外
  3. 销毁时强制 grab_release()，避免下一次弹窗抓不到
  4. 回调里的未捕获异常不再静默：写入
     %APPDATA%\OpenRF_Studio\error.log 并弹窗告知
  5. 打包成窗口程序后 sys.stdout/stderr 为 None，已接到 runtime.log，
     避免任何 print/回溯把事件循环带崩

二、新增自检：装完可以直接验证对话框

  OpenRF_Studio.exe --selftest

  逐个打开「反向计算 / 匹配计算器 / 滤波器向导 / 传输线计算器 /
  线阻抗 / L 型匹配 / AI 设置 / 元件参数」，校验每个都确实可见
  且成功抓取，全部通过返回 0，否则返回 1。

  发布前已在源码与打包后的 exe 上各跑一遍，均通过。

OpenRF Studio v3.0.1  交付说明补充（2026-11-02）
============================================================

一、拖动窗口卡顿修复

【病根】直角图/Smith 圆图的画布直接绑在 <Configure> 上，每收到一个
  尺寸变化事件就整图重绘一次。拖动一次窗口会触发几十上百个事件，
  主线程被绘图吃满，表现为窗口拖不动、鼠标一顿一顿。

【实测】带真实曲线（401 个扫频点）时单次重绘 3.7 ms；
  拖动 100 帧 = 372 ms 的纯绘图开销。

【修法】尺寸同步更新、重绘合并：
  - _cw/_ch 仍然在事件里立刻更新（绘制代码随时要读，不能延迟）
  - 重绘改为 33 ms 后的定时器统一触发一次，期间的事件全部合并
  - 尺寸没变时直接不排重绘
  - 画布销毁时取消未执行的定时器，避免销毁后回调报错

【结果】同样拖动 100 帧：372 ms -> 3.7 ms，重绘次数 100 -> 1。
  100 个事件本身的处理耗时 0.072 ms。

二、验证
  13 个测试套件全部通过（含新增的 45 项技能测试）。

OpenRF Studio v3.0.0  交付说明补充（2026-11-01）
============================================================

一、AI 对话加了「专业角色前置」
  对话面板顶部新增「对话角色」下拉框，两种角色各有独立的判断体系：

  1) 无线网络工程师（默认）
     - 先确认系统指标（发射功率、天线增益、馈线损耗、灵敏度、
       解调门限、所需余量），不齐不轻易下结论
     - 链路预算按 dB 逐项列，末尾必须给出「通/不通/余量多少 dB」
     - 级联 NF / IIP3 走 Friis；覆盖分析必须点明用的是哪个模型
       （自由空间 / Hata / COST-231 / 3GPP UMi）及其适用边界
     - 回波损耗判据按链路能容忍多少失配损耗来定，不一律套 -10 dB

  2) 天线系统设计师
     - 先定电尺寸与带宽，再谈形式（振子/贴片/八木/喇叭/螺旋/阵列）
     - 方向图讲三件事：主瓣增益、波束宽度、副瓣，三者互相牵制
     - 匹配用 Smith 圆图语言；L 型只能窄带，多级才展宽
     - 阵列必谈栅瓣，给判据 d < lambda / (1 + |sin theta_max|)
     - 明确声明本软件做电路级仿真，不含全波电磁求解

  两个角色都带硬边界：不编造器件手册参数、不臆造标准条款号、
  无数据支撑的数标「假设」；彼此划清转交范围（系统链路归工程师、
  辐射体归天线设计师）。

  关键设计：角色段之后紧跟一行声明——JSON 输出协议与动作格式的
  约束优先于角色设定。否则模型为了演好身份容易破坏 JSON 结构，
  把原本能用的自动执行链路弄坏。

  角色选择持久化到 %APPDATA%/OpenRF_Studio/ai.json 的 persona 字段，
  关掉重开仍然记得；打开「AI 设置」再保存也不会被重置回默认。

二、AI 技能系统正式接入对话流程
  三个内置技能，纯本地计算，不联网、不需要模型：

  1) circuit.build（改电路，需确认）
     巴特沃斯低通/高通/带通/带阻综合，按阶数、频率、阻抗给出
     逐节元件值。命中后不直接改电路，而是生成「待应用提案」，
     必须点「应用」才写入。
     （注意：界面的 build_filter 动作目前只支持低通/带通；
       高通/带阻会给出完整元件表，但需要手工逐节添加。）

  2) plot.explain（只读，直接出结论）
     读取当前扫描结果，报响应类型、峰值/插损、-3dB 判据下的
     上下限频率与带宽、通带起伏、S11 最好/最差值，并说明哪些
     边界落在扫描范围之外——不假装知道范围外的数据。

  3) match.design（只读提案）
     L 型匹配综合：给定源阻抗、负载阻抗与频率，给出 Q 值与
     逐件元件值。支持 RL>R0、RL<R0 以及复数负载（先串联消容抗）。

  路由规则经过刻意的保守设计：
  - 中文关键词按字符数加权（两个字也够门槛），否则「带宽」这类
    高区分度的短词永远匹配不上
  - 会改电路的技能需要更高的命中分才触发——误触发只读分析无伤，
    误触发「重建电路」会把用户已有的网络冲掉
  - 参数从自然语言本地解析（阶数、GHz/MHz、源/负载阻抗、容性/感性），
    解析不到就用技能默认值，绝不编造数字
  - 未配置模型时，技能照常可用（这才是「断网也能用」）

三、顺带修掉的一个真 bug
  技能读取扫描数据时只认 dict，而界面里放的是 SweepResult 对象，
  导致「解读这条曲线」永远回答「还没有可解读的数据」。
  现在按引擎自己的公开方法（freqs / insertion_loss_db /
  return_loss_db）规整，保证解读的就是界面上看到的那条曲线。

四、验证
  - 新增 tests/test_skills.py，45 项断言，覆盖注册表、巴特沃斯原型、
    四种响应综合、匹配自洽性（反算 Zin 必须等于 Z0）、曲线解读、
    参数解析、技能派发与路由保守性
  - 全部 13 个测试套件通过：ai / skills / cleanroom / conformance /
    engine / features / io / match_ui / optimize / s2p / theme /
    topology / ui_logic

  2. S2P 元件：导入 2 端口 Touchstone，按频点插值 S→Y 参与求解；路径存工程。

【六、v1.3 新增：AI 辅助设计】
  1. 「AI 助手」页签：自然语言下指令（设计低通/带通、算微带线、阻抗匹配、改频、分析结果）。
  2. 模型可自定义：帮助 → AI 设置，填 base_url / 模型名 / 密钥 / 温度 / 超时；
     支持任意 OpenAI 兼容接口（OpenAI、DeepSeek、通义、Moonshot、智谱、
     本地 Ollama(/v1)、LM Studio(/v1)、vLLM、one-api 等），可拉取模型列表、测试连接。

【七、v1.2 新增】
  1. 反向计算（四个页签）：
     · LC 谐振：给频率与 L（或 C），反求另一个；
